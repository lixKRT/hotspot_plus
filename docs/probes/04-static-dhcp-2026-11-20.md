# 自建 DHCP / 固定 IP 真机记录

设备：OnePlus 8T KB2000，Android 16 / SDK 36，Magisk 31.1。

## 包版本与证据范围

- **包版本**：设备中间版本 `132961d2`，不是本次完整 diff。该包 `bin/hsp` 有 `wait_hotspot_ready`，但没有 `daemon_pids`；`bin/hspd` 有 `DHCP_TRIED`、`dhcp_release_placeholder_clients`，但没有 `wait_dhcp_ready`、`dhcp_drop_stale_placeholder`、daemon singleton；`lib/common.sh` 也缺少这些新函数。
- **设备配置**：`FIXED_GATEWAY=1`、`DHCP_ENABLE=1`、`ENFORCE_GATEWAY=1`、`AUTO_START=1`。其中 `ENFORCE_GATEWAY=1`、`AUTO_START=1` 是用户覆盖，不是仓库默认；仓库默认为 `1/1/0/0`。
- **是否本次 diff**：否。本记录用于定位占位地址和静态租约问题，不能作为当前 HEAD 的真机 PASS。
- **设备运行态**：记录当时 `wlan2 192.168.42.1/24`、1 个 `hspd`、1 个 `udhcpd`、`.105/.106` 邻居、无 `.254`；这只说明当时设备健康，不覆盖本次新增的完整生命周期、接口探针和 daemon singleton 逻辑。

## 现象

使用模块启动热点并请求固定网关后：

- `wlan2` 实际为 `192.168.42.1/24`；
- `udhcpd` 已运行并监听 67；
- `V40` 拿到静态绑定地址 `192.168.42.106`；
- 另一台已绑定设备 `Redmi-K70` 先拿到了系统 DhcpServer 的占位地址
  `192.168.42.254`；
- `hsp_dhcp` 拦截系统 DHCP 应答后，该客户端仍暂时保留 `.254`，
  且系统 DHCP 继续尝试下发。

## 根因

Android 的静态网关请求要求同时提供 `staticClientAddress`。系统 DhcpServer
在模块接管前的冷启动窗口内可能把这个占位地址先发给真实客户端。
模块原来的自建 DHCP 只拦截后续系统应答，没有处理已经落在客户端上的
占位地址。

## 当前处理

- 保留 `.254` 作为系统占位地址（动态池为 `.100–.200`，两者不重叠）。
- `hspd` 在 `udhcpd` 启动并装好拦截规则后，检查邻居表：
  - 拿到 `.254` 的客户端会被释放邻居项，触发重新租约；
  - 已绑定 MAC 但与绑定 IP 不一致的客户端同样释放；
  - 普通动态客户端不处理。
- 设备侧若仍显示 `.254`，断开重连一次即可让 `udhcpd` 重新下发绑定地址。

## 已验证

- 固定网关 `192.168.42.1/24` 被采纳。
- `udhcpd` 动态池 `.100–.200`，静态租约 `.106` 实际下发。
- `hsp_dhcp` OUTPUT 拦截规则安装成功。

## 待验证 / 风险

- 客户端在冷启动窗口拿到 `.254` 后，模块释放邻居项是否能让其立即
  重新 DHCP，取决于客户端系统的租约重试行为；最可靠的验证是
  断开/重连客户端。
- USB 共享的高并发 P2P 连接仍可能污染 Tethering BPF，测试时应区分
  Wi‑Fi 热点客户端与 USB 客户端。
