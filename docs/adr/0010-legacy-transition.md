# 让旧模块退役，而不是与它协作

状态：已接受

热点增强在运行时既不依赖 `oneplus8t_fixed_hotspot`，也不依赖它的特权助手。验证期间旧模块可以保留为回滚路径，但不得与热点增强同时运行开机启动服务。旧模块的 APEX 子网补丁不被继承。

所有权验证时，仅禁用旧模块的 `service.sh` 不够：旧模块的 `post-fs-data.sh` bind mount 仍可能固定子网，掩盖热点增强能否自行请求网关。验收运行必须整体禁用旧模块，同时保留其文件以便回滚。重新启用旧模块需要重启，且不得在热点增强验证期间进行。

安装和验收流程因此必须包含显式冲突检查：如果旧模块处于启用状态，必须提示用户禁用或移除它，然后再测试热点增强的所有权。两个 Magisk 模块 ID 不同，因此安装其中一个不会静默替换另一个；干净迁移必须是用户可见的步骤，而不是安装器的小动作。

## 影响

两个模块可以同时存在于磁盘，但同一时间只能有一个拥有开机热点启动和客户端地址行为。两者同时启用时的设备测试不算有效验收。
